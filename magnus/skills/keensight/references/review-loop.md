# 交付前评审闸

锋识交付的门槛**与 git push 同闸**：**3 个并行 fresh sub-agent / 连续 2 轮全绿才交付**。

- **轮内冻结草稿**：3 个 agent 评同一份 PDF / 源。
- **轮间冻结 prompt**：每轮起 fresh agent、给完全相同的 prompt（防时变暗示性，以得真改进）。
- 任一 agent 标出实质问题 → 先修问题、计数清零、重新连续两轮。
- 连续两轮全绿 → 交付。

## 「绿」的判据（锋识版）

1. **有向图完整**——原语先定义后使用，无前向悬空引用，起点到前沿主干不断链。
2. **每条边严谨架桥**——无科普式跳跃，无「显然」搪塞。
3. **双轨齐备**——每节点规格 / 推演分明；**只读规格轨即自洽可懂**。
4. **深度优先**——未跑偏到批评 / 局限 / 可观测原语批判等支线。
5. **知三陈一可验**——抽查任意陈述皆有据可查、非臆造。
6. **语言干净**——流利中文、无中英混杂；著名术语用英文。
7. **公开可接受**——完备自包含、署名齐、PDF 高可读、可直接公开。

## 推荐评审 prompt（轮间冻结此文）

> 通读这份锋识（PDF + 源）。逐条核：有向图是否完整无前向悬空引用、每条边是否严谨架桥无科普跳跃、规格轨能否独立读懂、是否深度优先未跑偏、抽查陈述是否有据可查、中文是否干净无中英混杂、是否完备自包含可公开。挑出一切实质问题；没问题就明确说「全绿」。不要为了应付而放水，不要让熵增加。
